# The Unleash Tribe — Product Requirements Document

## Product

**The Unleash Tribe Daily Check In**

Version: **V1.0**

Purpose: replace manual WhatsApp accountability check-ins with a secure, structured and administratively manageable web platform.

---

## Core Product Rule

The product is an accountability platform.

Users do not manually declare a parent category complete.

A parent category becomes complete only when **all active required child tasks under that parent have been completed**.

Overall daily completion is calculated from completed required parent categories.

Example:

- 3 completed parents out of 7 required parents = `3 / 7`
- Percentage = `42.86%`, displayed rounded in the UI.
- A temporary eighth required parent makes the denominator `8` during its scheduled period.

## Dynamic Task Management

Tasks must NOT be hard-coded into the member application.

Admins can:

- create parent categories
- create child tasks
- mark parents required or optional
- mark children required or optional
- schedule tasks with start dates
- schedule tasks with end dates
- create temporary programs
- archive tasks
- preserve historical records

Examples:

- 31 Days of Scriptural Declaration
- Seven Days of Fasting
- Temporary monthly challenges

Deleting historical task records is prohibited.

---

## Accountability Window

The daily accountability period is not a normal midnight-to-midnight calendar day.

Default target workflow:

- opens: 10:00 AM community time
- closes: 6:00 AM the next day
- 2:00 AM activity belongs to the previous accountability date
- between closing and the next opening, task submission is unavailable

The timezone and opening/closing times are admin configurable.

## Daily Dashboard

The member dashboard must automatically display:

- member first name
- deterministic V1 avatar
- accountability date
- current streak
- overall completion percentage
- completed parent count
- total required parent count
- parent task cards
- child task buttons
- automatic parent completion status
- current accountability window state

Members never manually type:

- their name
- the date
- daily completion fraction
- completion percentage

Those values are generated by the application.

---

## Streak

A day counts toward the streak only when all required parent categories are complete.

An unfinished day does not break the streak until its accountability window closes.

Days before the member joined do not count against the member.

---

## Admin Accountability Reporting

V1 must allow admins to identify, for a selected accountability date:

- completed members
- incomplete members
- members who started but did not finish
- members who never visited / never submitted
- completion percentage
- historical backfills

Administrative history changes must be auditable.

## Membership and Roles

Roles:

- Member
- Admin

Admins can:

- review membership applications
- approve applicants
- reject applicants
- disable members
- restore members
- promote members to admin
- demote admins
- manage tasks
- manage onboarding questions
- review accountability records
- enter historical records

The system must never permit removal, disabling or demotion of the final active administrator.
